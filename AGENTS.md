# Repository Guidelines

## Project Structure & Module Organization

This is a Bun-powered Vite 8 + React 19 + TypeScript app for Anime Expo trip planning. Frontend code lives in `src/`. File-based TanStack Router routes are in `src/routes/`; shared route metadata is in `src/routes.ts`, and `src/routeTree.gen.ts` is generated by the TanStack router plugin and should be committed. Page implementations live in `src/pages/`, reusable UI in `src/components/`, trip data/helpers in `src/trip/`, and static/PWA assets in `public/`. The Cloudflare Worker API is in `worker/index.ts`.

## Build, Test, and Development Commands

- `bun install`: install dependencies from `bun.lock`.
- `portless ax26 vite`: preferred local dev flow. Portless starts Vite on an available strict port and exposes `https://ax26.localhost`.
- `portless ax26-feat-something vite`: use a worktree-specific Portless name when developing in a feature worktree.
- `bun run dev`: start Vite directly only when Portless is not being used.
- `bun run build`: run `tsc -b` and produce Cloudflare/client build output.
- `bun run lint`: run ESLint across the repo.
- `bun run lint:ox`: run Oxlint for an additional fast lint pass.
- `bun run typecheck:worker`: type-check only the Worker code.
- `bun run preview`: preview the built app in the Workers runtime.
- `bun run worker:deploy`: deploy with Wrangler.

## Coding Style & Naming Conventions

Use TypeScript and React function components. Match the existing style: two-space indentation, single quotes, no semicolons, and concise named exports. Components use `PascalCase` filenames and exports, for example `RootLayout.tsx`; hooks use `useX` naming. Keep route files in `src/routes/` small and delegate UI to page/component modules. Do not hand-edit `src/routeTree.gen.ts`; regenerate it through Vite/TanStack Router.

## Testing Guidelines

There is no dedicated test suite yet. Before handing off changes, run `bun run lint`, `bun run build`, and `bun run typecheck:worker` when Worker code changes. For route changes, verify browser-history paths such as `/timeline`, `/bookings`, and `/ledger`, plus API paths like `/api/health`.

## Commit & Pull Request Guidelines

Recent history uses short imperative messages, sometimes with conventional prefixes, for example `Install TanStack file router`, `fix: css`, and `feat: add bookings and ledger pages with hash routing`. Prefer a concise subject that names the user-facing or architectural change. PRs should include a short summary, validation commands run, screenshots for visual UI changes, and any Cloudflare routing or deployment notes.

## Security & Configuration Tips

Keep local/generated deployment state out of git, especially `.wrangler` and `.dev.vars*`. SPA routing depends on `wrangler.jsonc` using `assets.not_found_handling` and `run_worker_first` for `/api/*`; preserve that split so browser routes serve the app shell while API routes reach Hono.

## Agent-Specific Instructions

Do not create and kill your own dev server for routine checks. The user runs this project through Portless by Vercel, for example `portless ax26 vite`, which handles port selection, proxying, HTTPS, and Vite startup. In feature worktrees, use a distinct Portless name such as `portless ax26-feat-something vite`, then verify against that generated `.localhost` URL. Use the existing Portless URL for browser verification when it is already available.
