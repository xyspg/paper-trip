# Repository Guidelines

PaperTrip (`papertrip`, deployed at papertrip.xyspg.moe) is a multi-tenant trip planner built with Bun, Vite 8, React 19, and TypeScript, served from a Cloudflare Worker. The public UI is a print-style "paper" theme; each trip also has an admin console.

## Architecture

- **Multi-tenant, one Durable Object per trip.** `TripDurableObject` (binding `TRIPS`, `worker/TripDurableObject.ts`) holds each trip's live state, audit log, and backups, addressed by `tripId`. Never assume a single trip.
- **D1 registry.** `DB` (database `papertrip`) stores the better-auth tables plus the registry (users, trips, memberships, invites) through `worker/registry.ts`. SQL migrations live in `migrations/`.
- **Auth and roles.** better-auth sessions (`worker/auth.ts`, client `src/auth/client.ts`) require the `nodejs_compat` flag. Local agents authenticate with signed bearer tokens (`worker/agentToken.ts`). `worker/index.ts` enforces role-scoped op allowlists: `PUBLIC_OPS` (anonymous, public trips only), `AGENT_OPS` (token agents), and `OWNER_OPS` (destructive bulk ops, owner-only). Unknown ops fail closed.
- **Per-trip timezone.** Each trip carries its own `base.timezone`. Derive any "now"/"today" from it (`todayIn`, `nowIn(trip.base.timezone)`), never hardcode a deployment-specific zone. Re-audit single-tenant assumptions when porting older branches.

## Project Structure & Module Organization

Frontend code lives in `src/`. File-based TanStack Router routes are in `src/routes/`; shared nav metadata is in `src/routes.ts`, and `src/routeTree.gen.ts` is generated by the router plugin and committed (do not hand-edit). Trip-scoped routes are `/t/$tripId/{timeline,bookings,ledger,admin.*}`. Unscoped trip-page paths return to `/`, the signed-in user's trip dashboard; `/invite/$token` accepts invites.

Page implementations live in `src/pages/` (the paper theme renders through the `Paper*` components); the per-trip admin console is in `src/admin/` (Base Web + styletron); reusable UI is in `src/components/`; trip data, hooks, ops, and types are in `src/trip/`; static/PWA assets are in `public/`. The Cloudflare Worker lives in `worker/`: `index.ts` (Hono app), `TripDurableObject.ts`, `registry.ts` (D1), `auth.ts`, `agentToken.ts`, `email.ts`.

## Build, Test, and Development Commands

- `bun install`: install dependencies from `bun.lock`.
- `portless papertrip vite`: preferred local dev flow. Portless starts Vite on an available strict port and exposes `https://papertrip.localhost`.
- `portless papertrip-feat-something vite`: use a worktree-specific Portless name when developing in a feature worktree.
- `bun run dev`: start Vite directly only when Portless is not being used.
- `bun run build`: run `tsc -b` and produce the Cloudflare/client build output.
- `bun run lint`: run Oxlint across the repo.
- `bun run fmt` / `bun run fmt:check`: format (or check) with oxfmt. Do not hand-format; let oxfmt own quotes, semicolons, and spacing.
- `bun run typecheck:worker`: type-check only the Worker code (`tsconfig.worker.json`).
- `bun run cf-typegen`: regenerate Worker binding types from `wrangler.jsonc`.
- `bun run preview`: preview the built app in the Workers runtime.
- `bun run worker:dev` / `bun run worker:deploy`: Wrangler dev / deploy.

## Coding Style & Naming Conventions

Use TypeScript and React function components with two-space indentation. Formatting is enforced by oxfmt, so match its generated output instead of applying a fixed quote or semicolon rule by hand. Components use `PascalCase` filenames and exports, for example `RootLayout.tsx`; hooks use `useX` naming. The React Compiler is enabled (`babel-plugin-react-compiler`), so avoid manual memoization unless profiling shows a need. Do not call `useEffect` directly: use `useMountEffect` (`src/useMountEffect.ts`) for one-time external setup, and prefer deriving state or handling work in event handlers over syncing via effects. Keep route files in `src/routes/` small and delegate UI to page/component modules. Do not hand-edit `src/routeTree.gen.ts`.

## Testing Guidelines

Before handing off changes, run `bun test`, `bun run lint`, and `bun run build`, plus `bun run typecheck:worker` when Worker code changes. For route changes, verify trip-scoped paths such as `/t/<tripId>/timeline`, `/bookings`, and `/ledger`; unscoped paths returning to `/`; invite acceptance (`/invite/<token>`); and API paths like `/api/health`.

## Commit & Pull Request Guidelines

Recent history uses short imperative subjects, sometimes with conventional prefixes, for example `feat: source Gemini model id from env var` and `fix: css`. Prefer a concise subject that names the user-facing or architectural change. PRs should include a short summary, the validation commands run, screenshots for visual UI changes, and any Cloudflare routing, D1 migration, or Durable Object migration notes.

## Security & Configuration Tips

Keep local/generated deployment state out of git, especially `.wrangler` and `.dev.vars*`. Secrets (better-auth secret, Google AI / Gemini key, email sender key) belong in Wrangler secrets or `.dev.vars`, never in `wrangler.jsonc` `vars`. SPA routing depends on `assets.not_found_handling: single-page-application` plus `run_worker_first` for `/api` and `/api/*`; preserve that split so browser routes serve the app shell while API routes reach Hono. `nodejs_compat` is required for better-auth. Durable Object class renames must ship as rename migrations in `wrangler.jsonc` so stored trip state survives.

## Agent-Specific Instructions

Do not create and kill your own dev server for routine checks. The user runs this project through Portless by Vercel, for example `portless papertrip vite`, which handles port selection, proxying, HTTPS, and Vite startup. In feature worktrees, use a distinct Portless name such as `portless papertrip-feat-something vite`, then verify against that generated `.localhost` URL. Use the existing Portless URL for browser verification when it is already available.
